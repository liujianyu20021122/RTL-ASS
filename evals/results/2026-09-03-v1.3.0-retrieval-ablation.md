# RTL-ASS 1.3.0 retrieval ablation — 2026-09-03

## Decision

The audited retrieval mechanism is executable and observable. In one isolated
off/on pair, both Codex runs produced independently correct RTL, complete
deliverables, current structured evidence, and compliant workflows. The empty
condition returned no knowledge record. The populated condition returned one
bounded record through a valid receipt and Codex then read that exact record
with `kb show --include-content`.

This pair does not establish correctness uplift or statistical significance:
both candidates passed. The populated condition took 359.992 seconds versus
336.620 seconds (+6.94%), used 1,112,684 versus 928,936 input tokens (+19.78%),
and used 13,369 versus 11,763 output tokens (+13.65%). Earlier diagnostic reruns
showed different cost directions, reinforcing that these are one-pair
observations rather than expected-cost estimates.

## Protocol

- `codex-cli 0.152.1`, `gpt-5.6-sol`, high reasoning, one serial off/on pair,
  and a 900-second per-run timeout.
- Both conditions used the same embedded-release RTL-ASS Skill, runtime, task,
  public fixture, hidden grader, open-source tools, resource policy, and
  externally isolated disposable workspace.
- The only intended treatment was the `eval:retrieval` namespace: empty for
  off, or populated with one reviewed generic signed-expression diagnostic
  card for on.
- The pack admitted only a `design-pattern` record and passed direct artifact
  hash separation plus the explicit human semantic-review marker. It contained
  no task source, test, reference implementation, patch, answer, or grader
  output.
- Raw JSONL remains ignored local evidence. The sanitized report retains
  observable commands, file changes, receipts, resource telemetry, hashes,
  usage, and independent grades without retaining hidden reasoning content.

## Defects found and corrected

The first diagnostic smoke used strict all-token FTS matching for a natural
language query and returned zero records in both conditions. This exposed a
retrieval usability defect rather than a positive effectiveness result. Search
now requires an explicit `all` or `any` match policy, records that policy in the
receipt, and never silently falls back between them.

A subsequent trace review found that paths such as an equivalence log could be
misclassified as a new EDA command after the ready gate. Command classification
now parses exact helper subcommands and executable invocations; a regression
proves that reading a log is not counted as executing its producer.

Receipt replay originally trusted the current evaluation database. A run could
therefore delete or rewrite that database before presenting a self-consistent
receipt. The harness now hashes the prepared database, requires the post-run
bytes to match, validates its append-only audit chain, and only then replays the
query. Deletion, byte changes, forged results, and invalid audit state are
separate rejecting cases.

The shared waveform validator initially checked the container and status but
not every event or first-divergence field. It now rejects events outside the
declared window, events for unselected signals, incomplete divergence objects,
same-signal comparisons, and non-null objects for non-found results. This
hardens all evaluator task classes at one boundary rather than adding a
signed-width exception.

Finally, a cgroup disappearing after process exit could overwrite the last
valid all-zero `memory.events` snapshot with an empty object. The monitor now
retains the last successful snapshot and invalidates a run that never observed
the events file. The final pair above used all corrected boundaries.

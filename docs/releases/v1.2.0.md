# RTL-ASS 1.2.0

RTL-ASS 1.2.0 strengthens the open-tool execution layer while keeping Codex as the RTL author and decision-maker. It combines the unreleased post-1.1 audit hardening with one shared compile contract, native formal/equivalence drivers, and a self-contained Skill release.

## Tool and evidence changes

- Added a strict CompileManifest contract for ordered sources, library files, include directories, Verilog/SystemVerilog language mode, defines, top parameters, and top module. Every source-based adapter consumes the same normalized, content-bound identity.
- Added Verilator `--binary` simulation alongside Icarus simulation.
- Added native SymbiYosys bounded assertion evidence and EQY equivalence evidence. Depth, initialization, input domain, strategy, solver, exact compile inputs, driver markers, and counterexample traces are recorded; missing or ambiguous output is blocked rather than inferred as pass or fail.
- Added one public dispatch boundary for simulation, formal, and equivalence backends so CLI routing and direct API use share backend policy.
- Fixed assertion-scope auditing across Yosys versions that represent elaborated assertions as either `$assert` or `$check` cells.
- Normalized version and simulation-process attribution so tool absence, launch failure, compiler rejection, and missing compile artifacts cannot be conflated; failed probe diagnostics no longer masquerade as tool versions.

## Integrity and release controls

- Sequential Yosys equivalence uses a bounded miter/SAT check with an explicit zero-default initialization policy and preserves source initial values.
- Workflow evaluation reuses central evidence validation, rejects forged or escaped subjects/artifacts, recognizes only executed Skill reads/helpers, and terminates timed-out process groups before grading.
- OpenSTA and native SBY/EQY CI gates build source-pinned matching toolchains and execute positive and negative fixtures without accepting skips.
- Yosys synthesis has separate fast generic-structural and Liberty-mapped modes. The mapped mode binds the library and does not synthesize duplicate functional cell models. `verify sta --synthesis-evidence` validates and consumes its exact emitted Verilog netlist.
- The isolated Codex evaluator gives each run a writable private temporary directory and reports the cgroup kernel memory peak separately from sampled current memory.
- The Skill ZIP now embeds the validated pure-Python wheel plus its checksum. Its launcher verifies the bundled runtime before import, and CI executes the extracted Skill under isolated Python without a separate wheel installation.
- Release assembly validates wheel/sdist structure before creating auxiliary assets and requires byte-identical double builds.

## Boundaries

Formal results remain bounded to the recorded depth and assumptions. EQY uses its recorded SBY strategy and does not turn an unproved partition without a counterexample into a disproved design. OpenSTA evidence is not physical signoff. The historical v1.1.0 six-class workflow report is not relabeled as a v1.2.0 effectiveness evaluation.

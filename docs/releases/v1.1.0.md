# RTL-ASS 1.1.0

RTL-ASS 1.1.0 strengthens the vendor-neutral Codex RTL workflow with an audited local corpus, six executable workflow classes, and stricter evidence identity. Codex remains the design and coding agent; RTL-ASS supplies RTL-specific guidance, retrieval, and deterministic open-source verification support.

## Highlights

- Added a reproducible admission policy and file-level lock for 1,429 reviewed Verilog/SystemVerilog files across seven isolated namespaces. Upstream HDL remains local and is not redistributed in the release.
- Added six paired Codex workflow classes covering specification-to-RTL, FIFO repair, RTL/testbench attribution, SystemVerilog signed-width semantics, native FST localization, and OpenSTA-driven timing refinement.
- Bound evaluation reports to prompt, fixture, hidden grader, harness, Skill, runtime, combined payload, and sanitized report identities.
- Added explicit defined/undefined equivalence input domains and included the selected domain in evidence identity.
- Added hierarchical leaf-name waveform matching and reproducible, bounded VCD/FST first-divergence evidence.
- Hardened evaluation isolation, activation detection, timeout accounting, candidate/deliverable separation, packaging, and bytecode-independent payload identity.
- Expanded strict mypy coverage to every Python module in `src`, `tests`, `tools`, and `evals`.

## Reviewed workflow result

The audit ran five skill-off/skill-on pairs for each of six task classes: 60 Codex runs in total. Skill-on activation and complete structured evidence were 30/30; skill-off was 0/30 for both. External candidate correctness was 30/30 on versus 28/30 off, and timely task success was 29/30 on versus 23/30 off.

These heterogeneous, transparent cases validate observable Skill activation and evidence behavior. They do not establish universal RTL correctness or efficiency uplift. One otherwise-correct skill-on FIFO run exceeded the 600-second budget, and skill-on used more input tokens in aggregate.

## Compatibility and upgrade

- Python 3.11 and 3.12 remain supported.
- The public CLI, evidence schema `1.0`, knowledge-pack schema `1.0`, and explicit database migration model remain compatible with the 1.x line.
- No proprietary simulator, synthesis, FPGA-vendor, or timing tool is required. Supported evidence is produced only by available open-source tools.
- Install `rtl_ass-1.1.0-py3-none-any.whl` and replace the installed `rtl-ass` Skill directory with the one from `rtl-ass-skill-1.1.0.zip`.
